## Найдена причина зависания на «Подключение»

### Конфиги easy-xray указывают адрес **185.245.35.92**, а не 194.48.142.252

Результат `ex.sh link` на сервере:
```
vless://...@185.245.35.92:443?security=reality&sni=duckduckgo.com...
```

В коде бота `XRayRemoteInterface._replace_server_ip()` заменяет IP в ссылке на `self.host` = **194.48.142.252**.

**Итог:** пользователь получает ссылку с IP **194.48.142.252**, хотя в easy-xray всё привязано к **185.245.35.92** (Reality, SNI duckduckgo.com, публичный ключ).

### Почему «зависает» на Подключение

Для Reality/XTLS важно:

- подключаться к правильному IP/домену;
- использовать SNI (`duckduckgo.com`);
- использовать публичный ключ (pbk), привязанный к этому серверу.

Если в ссылке стоит **194.48.142.252**, а настройки Reality (ключи, fingerprint) завязаны на **185.245.35.92**, TLS/Reality handshake может зависать или падать, и клиент остаётся в состоянии «Подключение».

## Варианты решения

### Вариант A: 185.245.35.92 — реальный адрес для клиентов

Если 185.245.35.92 — публичный IP/CDN, на который ведёт трафик:

- **не подменять IP** в `get_xray_url` — использовать ссылку, как возвращает `ex.sh link`;
- в `update_vless_url_ip` при миграции с 89.40.233.3 заменять на **185.245.35.92**, а не 194.48.142.252.

### Вариант B: 194.48.142.252 — корректный адрес

Если должен использоваться 194.48.142.252:

- в easy-xray нужно перенастроить шаблоны и адрес в конфигах на 194.48.142.252;
- тогда замена в боте на 194.48.142.252 будет корректной.
